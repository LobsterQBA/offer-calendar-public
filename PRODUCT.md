# Product

## Register

product

## Users

Analysts reviewing public internet-offer observations, and repository visitors assessing how the system works. A visitor should understand the purpose before installing anything; an analyst should reach the original evidence behind a candidate change in a few clicks.

## Product Purpose

Turn captured offer wording into reviewable daily change candidates. Preserve the difference between a supported change, extraction drift, and missing evidence. The public demo teaches that workflow with synthetic records.

## Brand Personality

Clear, measured, inspectable. Use concrete source examples and plain English. Prefer an honest limitation over an unsupported business claim.

## Anti-references

Generic AI tool marketing, decorative KPI counters, invented accuracy claims, and dashboards that hide failed collection behind a reassuring empty state.

## Design Principles

- Lead with the task: find a day, inspect a change, read its evidence.
- Give first-time visitors a populated example immediately.
- Make original wording and collection status easy to inspect.
- Label synthetic input where it appears, including published screenshots.
- Separate optional cloud integration from the local learning path.

## Accessibility & Inclusion

Use text labels alongside color, visible keyboard focus, readable contrast and native form controls. Keep prose compact. Allow the calendar to scroll on narrow screens without making the whole page overflow.
